# 应用 2FA 接入应用锁真实门禁 — 详细设计方案

## 1. 目标与范围

给应用锁增加 TOTP 两步验证门禁：**密码验证通过后，还须输入手机验证器（Authenticator）动态码**才能解锁。覆盖全部锁定路径（手动/快捷键/启动锁定/恢复锁定/命令面板）。含注册向导（扫码）、一次性恢复码（防丢设备死锁）、主进程级防暴力冷却。**本期不做**：动态改动现有 `app-2fa:*` 测试链路（保留不动）、可信设备记忆、硬件密钥（FIDO2）。

## 2. 现状关键事实（已核实到行号）

- 应用锁：`electron/main/module/appLock.ts`（362 行）。密码 = 用户口令加密哨兵串（`vault/crypto.ts` AES-256-GCM + PBKDF2 200k），存 `basic_info.appLockVault`；锁定态权威在主进程 `isLocked`，`broadcastLockState()` 广播；`app-lock:unlock`(L306) 校验通过即 `unlockAppNow()`。
- 锁屏 UI：`src/layout/AppLock.vue`（挂载于 `src/layout/index.vue:89`，仅主窗口有）。**输错 5 次 30 秒冷却目前是纯前端计时**，可被刷新渲染进程绕过。
- 2FA 现状：TOTP 引擎在 `electron/main/module/twoFactor/otp.ts`（`generateTotp`/`randomBase32Secret`/`buildOtpauthUri`，**无独立 verify 导出**）；`app-2fa:*`（twoFactor.ts:211-285）的 secret 寄生在「2FA 保险库」加密文件里，**强依赖用户手动打开保险库** —— 启动锁定时保险库必然未打开，直接复用会导致门禁死锁。无限速无冷却。
- 二维码 L2 已备好：`showQrCode()`（`src/components/qrcode/service.ts`）可直接展示 otpauth URI（不写 qr_history，满足 twoFactor.md 红线）。

## 3. 关键设计决策

| 决策 | 选择 | 理由（备选） |
|---|---|---|
| 门禁密钥存哪 | **独立存 `basic_info` 新键 `appLock2faVault`，用应用锁密码加密** | 自洽闭环：校验第一步验密码成功后主进程已持有正确口令，可直接解密 secret 做 TOTP 校验，无需新密钥设施。（备选①寄生 2FA 保险库→启动锁死锁，否决；备选②设备主密钥加密→强度=混淆，且改密码/换机语义混乱） |
| 解锁顺序 | **两步：密码 → TOTP**（而非单表单双输入） | 行业标准；密钥解密天然依赖密码先验证成功 |
| 丢设备恢复 | **启用时生成 10 条一次性恢复码**（明文仅展示一次，存 SHA-256 哈希） | 无后门前提下唯一可行恢复路径，对齐 fileVault「忘记密码不可恢复」哲学；复用先例：恢复码哈希不可逆可直接落库 |
| 防暴力冷却 | **计数/冷却移到主进程**（密码+TOTP 共用计数，5 次→30s） | 修复现有纯前端冷却可绕过的缺陷；渲染端仅做倒计时展示 |
| verify 实现 | 抽 `verifyTotpCode()` 到 `otp.ts`（±1 步 + `timingSafeEqual`），`app-2fa:verify` 同步改为调用它 | 收敛 twoFactor.ts 内联重复逻辑，比对防时序侧信道 |

## 4. 数据模型（basic_info 单键，GCM 完整性保护）

`appLock2faVault` 值 = JSON：
```json
{ "v": 1,
  "envelope": "<VaultEnvelope>",       // encryptVault([payload], 应用锁密码)
  "createdAt": "ISO", "confirmedAt": "ISO" }
```
信封内 payload（解密后才可见）：
```json
{ "secret": "base32", "recoveryHashes": ["sha256hex"], "algorithm": "SHA1", "digits": 6, "period": 30 }
```
- 恢复码明文格式 `xxxxxx-xxxxxx`（`crypto.randomBytes(6).toString('hex')`），哈希=sha256(去 `-`)，命中即从数组移除并回写。
- TOTP 参数固定 SHA1/6 位/30s（与主流验证器默认兼容）。
- 关闭应用锁（clear-password）→ 连带删除本键；改密码 → 用新密码 re-wrap 信封。

## 5. 主进程设计

### 5.1 新文件 `electron/main/module/appLock2fa.ts`（门禁子系统，与 appLock.ts 职责分离）

导出：
- `initAppLock2fa()`：注册 `app-lock:2fa-*` 通道（由 `initAppLock()` 末尾调用，保持初始化内聚）。
- `is2faEnabled(): Promise<boolean>`：读键判存。
- `createPending2fa(password, senderId): string`：解锁第一步成功后建会话 `{ token: randomUUID(), password, expiresAt: now+120s, senderId }`。
- `consumePending2fa(token, code, senderId): Promise<Verify2faResult>`：校验会话（TTL+sender 一致）→ 解信封 → 6 位纯数字走 TOTP（±1 步、timingSafeEqual）；否则按恢复码匹配（命中即消耗回写）。成功返回 `{ ok, usedRecovery?, recoveryRemaining? }`，失败计入冷却。
- `rewrap2fa(oldPwd, newPwd): Promise<boolean>`、`purge2fa(): Promise<void>`：供 appLock.ts 改密/清密钩子。
- `registerLockFailure(): { cooldown: boolean, retryAfterSeconds: number }`：统一失败计数（含密码步），`failCount >= 5` → `cooldownUntil = now+30s`；内存变量，重启清零（文档注明局限）。
- `isCoolingDown(): number`：剩余秒数，冷却期内 unlock/verify-2fa 直接拒绝。

### 5.2 新增 IPC 通道

| 通道 | 类型 | 入参 → 出参 |
|---|---|---|
| `app-lock:2fa-get-config` | handle | `{ enabled, enrolledAt, recoveryRemaining }` |
| `app-lock:2fa-enroll-start` | handle | `{ password }` → 先 verifyPassword → 生成 pendingEnroll（secret + 5min TTL）→ `{ ok, uri, secret }`（uri/secret 仅此一次回传，先例：app-2fa:enroll） |
| `app-lock:2fa-enroll-confirm` | handle | `{ code }` → ±1 步匹配 pendingEnroll → 落库信封+10 条恢复码 → `{ ok, recoveryCodes: string[] }`（明文仅此一次） |
| `app-lock:2fa-enroll-cancel` | handle | 清 pendingEnroll |
| `app-lock:2fa-disable` | handle | `{ password, code }` → 双因子校验 → 删键 → `{ ok }` |
| `app-lock:2fa-recovery-regenerate` | handle | `{ password, code }` → 同上校验 → 新 10 条 → `{ ok, recoveryCodes }` |
| `app-lock:verify-2fa` | handle | `{ token, code }` → 成功 `unlockAppNow()`+广播 → `{ ok, usedRecovery? }`；失败 `{ ok:false, remainingAttempts?, retryAfterSeconds? }` |

### 5.3 `appLock.ts` 改动点（最小侵入）

- `app-lock:unlock`：冷却检查 → `verifyPassword` 失败走 `registerLockFailure()` 并在返回值扩展 `{ matched, remainingAttempts?, retryAfterSeconds? }`；成功且 `is2faEnabled()` → 不解锁，`createPending2fa()` 返回 `{ matched:true, need2fa:true, token }`；未启用维持现状直接解锁。
- `app-lock:set-password`：入参扩展 `{ text, current? }`（改密模式渲染端传当前密码）；成功后若门禁开启 → `rewrap2fa(current, text)`；有门禁但缺 current → 返回错误（防御）。
- `app-lock:clear-password`：成功后 `purge2fa()`。
- `app-lock:get-state`：返回值加 `twoFactorEnabled`。
- 文件头注释补充门禁说明。

### 5.4 `twoFactor/otp.ts` 新增

`verifyTotpCode(secretBase32, code, opts?): boolean`：清洗数字 → offset -1/0/+1 逐个 `generateTotp` → `crypto.timingSafeEqual` 比对。`twoFactor.ts` 的 `app-2fa:verify` 改为调用它（行为不变，仅收敛）。

## 6. 渲染端设计

### 6.1 `src/store/useAppLock.ts` 扩展
- `unlock()` 返回完整结果对象（matched/need2fa/token/remainingAttempts/retryAfterSeconds）。
- 新 action：`verify2fa(token, code)`、`get2faConfig()`、`enrollStart(password)`、`enrollConfirm(code)`、`enrollCancel()`、`disable2fa(password, code)`、`regenerateRecovery(password, code)`。

### 6.2 锁屏 UI（`src/layout/AppLock.vue` + 新子组件）
- AppLock.vue 增加两步状态机：`step: 'password' | 'totp'`；unlock 返回 `need2fa` → 切 TOTP 步、token 存内存；`watch(locked)` 解锁/重锁时复位到密码步。
- 新组件 `src/layout/components/AppLockTotpStep.vue`（保持 AppLock.vue 体量可控，符合「功能分割」约定）：6 位码输入（`maxlength=6` + `inputmode=numeric` + 回车/满 6 位自动提交）、「改用恢复码」切换（输入框切普通文本）、错误提示（剩余次数）与冷却倒计时（由主进程 `retryAfterSeconds` 驱动本地 setInterval 展示，AppLock.vue 密码步同步改为该模式、删除本地 failCount 逻辑）。
- 样式沿用现有锁屏毛玻璃 token 风格（rgba 遮罩沿用现状写法，不新增硬编码色值）。

### 6.3 设置页（安全与隐私区块）
- `AppLockSetting.vue` 在「已启用」区块内加一行「两步验证（TOTP）」：状态徽标（未启用/已启用·恢复码剩 N）、开关（开启→向导；关闭→双因子确认弹窗）+「重新生成恢复码」按钮。
- 新组件 `src/views/setting/components/TwoFactorGateWizard.vue`（el-dialog 四步向导，`mode: 'enroll' | 'regenerate'` 复用同一流程）：
  ① 验证当前密码 → ② 调 `enrollStart` 展示二维码（`showQrCode({ content: uri })`，不落 qr_history）+ base32 密钥文本供手动录入 → ③ 输入手机当前 6 位码确认 → ④ 恢复码一次性展示（复制全部/确认已保存才能关闭）。
  - regenerate 模式：跳过②③（凭密码+当前动态码校验）直接出恢复码。
- 关闭门禁：弹窗输入密码 + 当前动态码（或恢复码）→ `disable2fa`。

## 7. 安全考量

- secret/URI 绝不进 `qr_history`、不持久渲染端（enroll 一次性回传除外，与既有先例一致）。
- `timingSafeEqual` 防时序；pending2FA 会话 120s TTL + `sender.webContents.id` 绑定（其他窗口/重载后旧 token 失效）。
- 恢复码哈希存储、一次性消耗；冷却计数在主进程（跨渲染端刷新有效；**应用重启清零**——诚实注明，与现状一致不倒退）。
- TOTP 依赖本机时钟（twoFactor.md 红线沿用）；时钟漂移大时用恢复码兜底。
- 忘记密码 + 丢失全部恢复码 = 无法解锁（无后门）；向导 UI 明确警示。
- `appCache` 导出 JSON 会含信封密文（与 `appLockVault` 现状一致，PBKDF2 200k 离线爆破代价可接受，文档注明）。
- 渲染端零 `import electron/*`；全部走 IPC。

## 8. 边界与兼容

- **未设密码**：向导入口隐藏（门禁只能在 hasPassword 后开启）。
- **2FA 保险库关闭/未安装**：门禁完全独立，不受影响（这是本方案核心改进点）。
- **备份/恢复**：`basic_info` 随 `.jlbak` 走，门禁数据随行，恢复后密码不变即可解锁。
- **数据损坏**（信封解密异常，理论不发生）：`verify-2fa` 返回明确错误码，锁屏提示改用恢复码；不做绕过后门。
- **旧 `app-2fa:*` 测试链路**：保留不动，twoFactor 页测试小窗不受影响。
- 启动期零写入（遵守 risks#24 禁启动热路径 upsert），所有写发生在用户交互 handler 内。
